Where Can Rust Applications Run?

A practical guide to Windows, Apple macOS, Linux, mobile devices, and legacy systems—with a focus on distributing the applications you build, not just installing the Rust compiler.

The essential distinction

Running an app is different from compiling one

Rust compiles source code into native machine code. People using your finished application normally do not need Rust, Cargo, or a Rust compiler installed. They do need an executable built for their operating system and processor, plus any libraries required by the application.

Windows

Compile a native .exe for supported Windows targets.

macOS

Build executables for Intel or Apple Silicon, commonly packaged in a .app .

Linux

Produce native ELF executables, possibly packaged for a distribution.

Not one universal binary: Most cross-platform Rust software uses one shared codebase but produces separate builds for Windows, macOS, Linux, and different CPU architectures.
01 / Desktop systems

Microsoft Windows

Modern Rust's standard Windows compilation targets are intended for Windows 10 and newer. Older Windows editions may run Rust applications when built with specific legacy toolchains or specially configured targets; compatibility is not automatic.

Windows edition Running Rust applications Practical guidance
Windows 11 Supported Modern x64 and ARM64 builds.
Windows 10 Supported Standard modern Windows Rust builds; match CPU architecture.
Windows Server (modern releases) Supported Check release, APIs, libraries, and intended architecture.
Windows 8 / 8.1 Legacy / custom Typically requires older toolchains and careful testing.
Windows 7 Special build Specialized 64-bit Windows 7 target or older compatible toolchain; not a standard Windows 10+ executable.
Windows Vista / XP Specialized only Unsupported by normal modern targets; experimental/community legacy approaches may exist.

Rust 1.78 changed the minimum operating-system version for standard Windows targets to Windows 10. A Rust program's GUI framework and linked dependencies can raise that minimum further.

02 / Desktop systems

Apple Macintosh

Intel-based Macs

Use the x86_64-apple-darwin target. Rust supports producing binaries for many older Intel Mac operating systems; the stated minimum for the standard target is macOS 10.12.

Apple Silicon Macs

Use aarch64-apple-darwin for M-series Macs. The standard target starts at macOS 11, the first macOS release supporting Apple Silicon.

A macOS application may combine Intel and Apple Silicon binaries in a Universal 2 package. The GUI toolkit, third-party libraries, code signing, and app notarization can affect how you distribute the finished app.

The operating system must itself support the Mac's hardware; an application cannot run on a macOS version that the computer cannot install.

03 / Desktop & server systems

Linux and Unix-like systems

Rust has strong support for mainstream Linux distributions and multiple CPU architectures. Compatibility with older systems depends on the Linux kernel, C library, and any dependencies you bundle or link dynamically.

System Support Notes
Ubuntu, Debian, Linux Mint Strong Common desktop and server distributions.
Fedora, Arch Linux Strong Modern desktop and developer environments.
Raspberry Pi OS Available Use the ARM target matching Pi hardware and 32-/64-bit OS.
FreeBSD Available Native target support; verify exact tier and version.
OpenBSD, NetBSD Target-dependent Less universal testing and library compatibility.
ChromeOS Conditional Via a compatible Linux environment or other supported runtime.

For some common Linux GNU targets, documented operating-system baselines include Linux kernel 3.2 and glibc 2.17. That does not guarantee every third-party package works on those versions.

04 / Beyond the desktop

Phones, browsers, and embedded devices

iPhone & iPad

Rust can implement native application logic and libraries. Apple-specific app tooling and packaging are still necessary.

Android

Rust can compile native libraries and components for Android devices across supported CPU architectures.

Web browsers

Rust can compile to WebAssembly for browser-based functionality, typically with JavaScript or web UI integration.

Raspberry Pi

Build native Rust executables for Linux on compatible ARM systems.

Embedded hardware

Rust supports many microcontrollers and specialized processors, often without a conventional operating system.

Servers

Rust services run on compatible Windows and Linux server environments, including cloud and on-premises machines.

05 / Application delivery

Typical Rust compilation targets

Consider a graphical application built from one shared Rust source tree. You would usually create these distinct builds:

Destination Rust target triple Typical delivery
Windows x64 x86_64-pc-windows-msvc .exe or installer
Windows ARM64 aarch64-pc-windows-msvc .exe or installer
macOS Intel x86_64-apple-darwin Executable or .app
macOS Apple Silicon aarch64-apple-darwin Executable or .app
Linux x64 (GNU) x86_64-unknown-linux-gnu ELF binary / package
Linux ARM64 (GNU) aarch64-unknown-linux-gnu ELF binary / package

Cross-compiling from one computer is sometimes possible, but platform-specific SDKs, linkers, frameworks, code-signing, and testing can require separate build environments.

Four compatibility checks before shipping

1
OS and minimum version

Confirm the exact operating systems that your binaries and their dependencies can support.

2
Processor architecture

Match x86, x64, ARM64, or another CPU target.

3
Native dependencies

Check libraries, graphics APIs, runtimes, and GUI toolkit requirements.

4
Real-device testing

Test installers and application behavior on every minimum OS version you promise to support.
